# YumoCut 软件与插件更新设计

日期：2026-11-20
状态：已确认方案方向，待书面设计复核
上游基线：`jub0t/Concat` 的 `v0.2.11`（提交 `6584d34971ae5e168f12cb475bdf58055b67d780`）
目标仓库：`Beau1314/YumoCut`

## 1. 背景与目标

当前工作目录最初只有安装后的 Concat 0.2.11 二进制文件，没有源码或 Git 历史。`concat-zh.exe` 的可能定制无法从二进制可靠还原，因此本设计不宣称保留它的独有修改；实现从上游同版本源码开始。

上游已经具备按 GitHub Releases 检查版本、下载对应安装包、验证 SHA-256、安装并重启的能力，但更新源固定为官方仓库，只在用户打开“版本”页时检查，也不管理用户效果包的远程更新。

YumoCut 是 Concat 的独立品牌衍生版，目标是：

1. 启动后自动检查软件与插件更新，发现更新时给出明确提示。
2. 用户点击一次“全部更新”即可更新当前支持的程序和已登记插件。
3. 所有下载先校验再安装；失败时保留旧版本，并提供可理解的错误信息。
4. 源码、发布包、许可证、修改说明和上游声明保持一致并可追溯。

## 2. 范围

### 包含

- 独立产品名称 YumoCut、自有图标和独立 Windows 安装标识。
- 更新仓库改为 `Beau1314/YumoCut`，仓库地址只保留一个权威配置来源。
- 启动自动检查、更新提示、手动重新检查、版本页状态展示。
- “全部更新”覆盖主程序与符合条件的用户效果包。
- 插件更新清单解析、兼容性判断、逐文件下载与 SHA-256 校验、暂存、替换、验证和失败回滚。
- GitHub Actions 构建 Windows x86_64 安装包并生成发布清单、插件清单和校验和。
- AGPL、第三方许可、商标边界、上游来源和衍生版修改文档。

### 不包含

- 从 `concat-zh.exe` 反推或恢复源码。
- 通用第三方插件商店、插件搜索、评分、账号或支付。
- 自动更新未在 YumoCut 清单中登记的用户包。
- 单独更新编译进主程序的内置效果；它们随主程序更新。
- 任意原生动态库或可执行插件。当前插件范围与上游一致，为声明式效果包。
- 本期其他平台的发布验收；保留其原有更新代码路径，但只承诺 Windows x86_64 的端到端发布验证。

## 3. 用户流程

### 启动检查

程序完成基本界面和效果目录初始化后，在后台检查一次更新。只有发现可用更新时才显示提示，内容包含新版本号和可更新插件数量。按钮为“立即更新”和“稍后”。“稍后”只关闭本次提示，本次运行不再重复弹出；手动检查不受限制。

离线、超时、DNS、TLS 或 GitHub 限流导致的启动检查失败只写入日志，不用错误弹窗打断编辑。用户在版本页手动检查时，相同错误必须显示在页面上。

### 版本页

“设置 → 版本”显示：

- 当前版本与最新版本。
- 已登记插件的当前版本、可更新版本和兼容性状态。
- “检查更新”和“全部更新”。
- 下载进度、正在处理的对象、成功结果或失败原因。

只有主程序有更新时，“全部更新”仍可用。只有插件有更新时，按钮更新插件而不启动主程序安装器。没有任何可更新对象时按钮禁用。

### 全部更新顺序

1. 获取正式发行版列表，忽略草稿、预发布和非纯数字版本标签。
2. 获取最新发行版的 `manifest.json` 与 `plugins.json`。
3. 计算主程序更新和插件更新的候选集合。
4. 下载全部候选文件到暂存目录，验证大小与 SHA-256；任一失败则不替换任何已安装文件。
5. 对每个插件建立旧版备份，替换目录并重新加载、解析和运行现有 GPU 安全试验。
6. 任一插件验证失败时，恢复本次涉及的全部旧插件，不启动主程序安装。
7. 插件全部成功后，如有主程序更新，复用上游安装和退出前保存流程；否则直接报告插件更新完成。

插件之间采用整组回滚，避免“全部更新”留下半组新版本。下载阶段允许保留完整且校验通过的暂存文件供重试，但不把暂存文件当作已安装内容。

## 4. 组件与边界

### `concat-host::updates`

继续负责主程序版本解析、发行版读取、平台安装方式识别、安装包下载校验、安装和重启。把仓库名与发行版 API 地址合并为由同一常量生成的逻辑，避免两处配置不一致。

### 新插件更新模块

放在 `concat-host`，只负责：

- 读取和校验 `plugins.json`。
- 从用户效果目录读取已安装包的 ID、格式与版本。
- 计算兼容且有更高版本的候选。
- 下载、校验、暂存、备份、替换与回滚。

它不直接操作 Slint 界面，也不决定何时提示。效果包的语义解析继续由 `concat-effects` 负责，GPU 安全试验继续由窗口层现有逻辑负责。

### `concat` 窗口层

负责启动检查调度、提示框、版本页状态、进度展示和调用整组更新。更新完成后复用 `reload_packages` 刷新目录和卡片缓存，不另建一套效果加载逻辑。

### 发布脚本

从仓库内 `plugins/` 下的包目录生成 `plugins.json`。脚本只接受通过 `concat-effects` 解析规则的包；发布前运行现有包测试和新增清单测试。清单中的下载 URL 指向同一 GitHub 发行版的插件文件资产。

## 5. 插件清单契约

发行版附件 `plugins.json` 使用 UTF-8 JSON：

```json
{
  "schema": 1,
  "plugins": [
    {
      "id": "author.effect-name",
      "version": 3,
      "format": 2,
      "min_app": "0.2.11",
      "files": [
        {
          "path": "effect.toml",
          "url": "https://github.com/Beau1314/YumoCut/releases/download/v0.2.12/author.effect-name-3-effect.toml",
          "bytes": 1234,
          "sha256": "64 个小写十六进制字符"
        }
      ]
    }
  ]
}
```

约束：

- `schema` 必须为 1；未知顶层字段可以忽略，未知文件字段可以忽略。
- 插件 ID 必须与暂存包内 `effect.toml` 的 `[effect].id` 完全一致。
- `version` 为正整数，只有高于本地版本才成为候选。
- `format` 不得高于当前程序支持的 `concat_effects::FORMAT`。
- `min_app` 使用与主程序相同的三段版本解析；当前版本低于它时不更新该插件。
- 每个包至少包含 `effect.toml`。允许 `effect.wgsl`、`fixtures.toml` 和相对子路径资源。
- 文件路径必须是规范化相对路径；拒绝空路径、绝对路径、盘符、反斜杠、`.`、`..` 和重复路径。
- SHA-256 必须为 64 个小写十六进制字符，大小必须与实际下载字节数一致。
- 单个插件最多 64 个文件、总计 32 MiB；超出限制拒绝整个插件。
- 清单中重复插件 ID 使整个清单无效，避免不确定选择。

SHA-256 提供完整性校验，信任根是 HTTPS 和指定 GitHub 仓库的发布权限，不把清单摘要宣称为抗仓库接管机制。

## 6. 文件系统与故障安全

- 下载位于应用数据目录的 `updates/plugins/`，不直接写入用户效果目录。
- 每个插件在独立暂存目录中重组，解析 ID、格式和版本后再进入替换阶段。
- 替换使用同卷目录重命名；旧目录先进入本次操作专属备份目录。
- 任何替换、解析或 GPU 试验失败都按相反顺序恢复旧目录，并清理未安装的新目录。
- 不因更新失败删除用户的其他效果包、项目或设置。
- 对同名但由用户手动修改过的旧包，只有用户明确点击“全部更新”才覆盖；操作前保留到备份目录，失败可自动恢复。
- 主程序安装继续经过上游的保存项目、关闭导出任务和退出确认流程，不绕过未保存工作检查。

## 7. 错误处理与可观测性

错误分为网络、清单无效、不兼容、摘要或大小不符、磁盘写入、替换、包解析和 GPU 试验失败。界面显示对象 ID、阶段和简短原因，完整路径与底层错误写入日志。

取消只影响尚未进入替换阶段的下载；进入插件替换后不允许中途取消。主程序安装器启动后，退出和重启行为保持上游实现。

启动自动检查与手动检查共享状态，避免并发请求。更新执行期间禁用重复更新按钮；下载进度按已接收字节和总字节计算。

## 8. 品牌与许可设计

- 产品对外名称为 YumoCut，使用新绘制的图标，不使用 Concat Logo 作为衍生版图标。
- Windows 使用新的 AppId、安装目录和包标识，避免被识别为官方 Concat 的升级包。
- 内部 crate 名、项目格式、效果 ID 命名空间和 API 可继续使用 `concat`，以保留项目兼容性；这些内部标识不作为产品来源声明。
- 保留上游 `LICENSE`、`LICENSING.md`、`THIRD_PARTY_NOTICES.md`、`TRADEMARK.md` 和源文件版权行。
- 新增 `FORK_NOTICES.md`，列明上游、基线提交、衍生版名称、修改日期、修改摘要、源码地址及“非官方版本”声明。
- README 明确项目为基于 Concat 的修改版，链接上游和对应源码，不暗示上游维护或背书。
- 发布包附带适用许可证和第三方声明；AGPL 对应源码与发布提交保持可定位关系。
- 编解码器专利、模型许可证和各字体许可证不因主程序许可证而改变；发布说明不声称提供额外专利授权。

## 9. 测试与验收

### 单元测试

- 仓库配置生成的 API 与下载地址均指向 `Beau1314/YumoCut`。
- 版本比较、预发布过滤、插件候选选择、`min_app` 与格式兼容性。
- 清单重复 ID、非法路径、错误摘要、错误大小、超限包和缺文件拒绝。
- 下载中断、摘要错误、写入失败、替换失败和 GPU 试验失败时的整组回滚。
- 未登记包、用户其他文件和设置在成功及失败路径均不变。
- 仅软件、仅插件、两者都有和没有更新时的界面状态。

### 集成验证

- 用本地静态服务器提供伪发行版清单和插件文件，完成发现、下载、校验、替换和重载。
- 构造一个正常效果包和一个故意损坏的效果包，验证后者触发整组回滚。
- 在 Windows 测试安装包覆盖升级、未保存项目提示和安装后重启。
- 发布前运行 `cargo fmt --check`、相关 `cargo test`、`cargo clippy --all-targets -- -D warnings`、本地化清单检查和插件清单检查。
- 当前机器没有 Rust 工具链，因此本地不能虚构编译结果；源码推送后由 GitHub Actions 执行实际构建与测试，只有日志通过才认定验证完成。

### GitHub 验收

- 远端仓库存在，默认分支与本地提交一致。
- 推送后重新读取远端 HEAD 和关键许可文件。
- 测试发行版包含安装包、`manifest.json`、`plugins.json` 和 `SHA256SUMS`。
- 用前一个测试版本实际收到更新提示并完成一次软件与插件更新，再核验版本号。

1. 提交设计文档并完成书面复核。
2. 制定逐步实现计划，先写失败测试再实现各模块。
3. 完成品牌、更新源、启动提示和主程序更新改造。
4. 完成插件清单、更新事务、界面和发布脚本。
5. 补齐许可与衍生版声明，运行本地可用检查。
6. 创建并推送 `Beau1314/YumoCut`，核验远端内容。
7. 运行 GitHub Actions，依据真实结果修复并生成测试发行版。
8. 完成端到端更新验收后报告仓库、发布和任何剩余限制。
